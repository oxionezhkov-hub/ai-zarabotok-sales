# Автопостинг в Threads

## Как устроено
1. Claude пишет посты на неделю в `queue/week-*.json`. Все они начинают со статусом `pending`.
2. Посты проверяют на странице проверки (артефакт «Threads: посты на неделю»): одобрить, отклонить, поправить текст, оставить комментарий.
3. Claude переносит решения со страницы в `queue/*.json`: статусы `approved` и `rejected`, поправленный текст попадает в поле `final_text`.
4. Workflow `.github/workflows/threads-publish.yml` запускается каждые 30 минут. Он публикует одобренные посты, у которых подошло время, и записывает в файл `published_id`.

## Секреты репозитория
- `THREADS_TOKEN` — долгоживущий токен Threads, обязателен.
- `GH_PAT` — необязательный. Это fine-grained токен GitHub с правом Secrets: read and write на этот репозиторий. Если он есть, workflow `threads-refresh-token.yml` каждый понедельник продлевает `THREADS_TOKEN` и сам его сохраняет. Если его нет, токен нужно обновлять вручную раз в 60 дней.

## Правила
- Пост, который опоздал больше чем на 3 часа (например, его одобрили поздно), не публикуется и получает статус `missed`.
- Проверка без публикации: `DRY_RUN=1 python3 threads/scripts/publish.py`
- Расписание по cron работает только из основной ветки репозитория.
